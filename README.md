# Overview Plus

A configurable version of the Home Assistant **Overview** dashboard.

Overview Plus is a custom dashboard strategy that rebuilds the structure of the built-in Overview
(Home Assistant 2026.2+) – overview page, one view per area, media and devices – and lets you change
what the built-in dashboard does not let you change:

- **Card rules:** show a different card for specific entities or devices, matched by entity, domain,
  integration, label, device, area and more (e.g. a custom thermostat card for all Better Thermostat entities).
- **Area overrides:** define your own highlighted sections for an area (title, icon, order, layout),
  matched by labels or integrations, followed by all remaining devices of that area.
- **Area tiles:** choose what an area's tile on the overview page shows instead of temperature/humidity.

Because every view is generated by Overview Plus itself, custom cards are in place on the first render –
no flicker from swapping cards after the built-in dashboard has loaded.

## Installation

### HACS

[![Open your Home Assistant instance and open the Overview Plus repository in HACS.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=financelurker&repository=ha-overview-plus&category=plugin)

1. Click the button above. It opens the repository in HACS on your Home Assistant and adds it as a
   custom repository if needed. Without the button: HACS → ⋮ → Custom repositories → add
   `https://github.com/financelurker/ha-overview-plus` as type *Dashboard*.
2. Install **Overview Plus** and reload the browser.

### Manual / development

1. Copy the contents of `src/` (including subfolders) to `config/www/overview-plus/`.
2. Settings → Dashboards → ⋮ → Resources → add `/local/overview-plus/overview-plus.js` as *JavaScript module*.

## Usage

Settings → Dashboards → **Add dashboard** → *Community dashboards* → **Overview Plus**.

To configure it, open the dashboard → ✏️ (edit). The visual editor shows:

- **Area layouts:** every area with its own layout is a collapsible block showing its sections and a
  short summary. Inside: badges, the toggles for remaining devices and automations, and the sections
  (title, icon, layout, label). *Refine selection*, *Entity filter* and *Primary entity* are form
  fields too: integration, domain, device class, manufacturer and model are dropdowns filled from your
  own installation (own values can be typed), plus devices, entities, device name and exclusions.
  *Add area* gives another area its own layout; *Remove area layout* returns it to the default view.
- **General:** card rules as blocks (action, card, name, icon, color, *Applies to* with the same
  selection fields, *Where and how*), and the options for the whole dashboard.

Only two things are YAML in the editor: options specific to a replacement card (*More card options*,
because every card type has different options), and – only if your configuration contains one – a
selection the form cannot show, such as an either/or list.

You can switch to the full YAML view at any time.

> Do not click **Take control** in that dialog: it converts the dashboard into a static copy of the
> currently generated cards, and Overview Plus no longer updates it.

The dashboard can also be created manually with:

```yaml
strategy:
  type: custom:overview-plus
```

Favorites, shortcuts and alerts are taken from the settings of the built-in Overview
(set `load_home_settings: false` to disable). Options of the built-in overview such as
`favorite_entities` can also be set directly and take precedence.

| Option | Description |
|---|---|
| `card_rules` | List of rules that replace, adjust or hide cards. |
| `area_overrides` | Per-area layout, keyed by area id. |
| `load_home_settings` | Use favorites/shortcuts of the built-in Overview (default `true`). |
| `lazy_render` | Render cards below the first screen of an area view only when they scroll into view (default `true`). |
| `strip_area_names` | Remove the area name from card names and device headings in area views, e.g. "Living room Ceiling light" → "Ceiling light" (default `true`). |
| `debug` | Log the generated area views and the section assignment to the browser console. |

### Match specifications

`card_rules` and `area_overrides` select entities with the same match syntax. All criteria in one
object must match (AND); a list of objects matches if any object matches (OR). Every criterion accepts
a single value or a list.

| Criterion | Matches | Example |
|---|---|---|
| `entity` | entity id | `climate.bath` |
| `domain` | entity domain | `climate`, `sensor`, `switch` |
| `device_class` | device class (`none` if unset) | `temperature`, `running` |
| `integration` | integration of the entity | `better_thermostat`, `mqtt` |
| `entity_category` | `none`, `config`, `diagnostic` | `diagnostic` |
| `label` | label on the entity **or** its device | `virt-guest` |
| `entity_label` / `device_label` | label on the entity / device only | |
| `device` | device id | |
| `device_name` | device name, regular expression | `^pve` |
| `manufacturer` / `model` | device manufacturer / model, regular expression | `Proxmox` |
| `area` / `floor` | area id / floor id | `proxmox`, `virtual` |
| `not` | nested match that must not match | `{ entity_category: diagnostic }` |

Tip: for devices that arrive through the same integration (e.g. several MQTT bridges), **labels**
are the most robust way to group them – assign them in the UI, no dashboard change needed.

### Card rules

```yaml
strategy:
  type: custom:overview-plus
  card_rules:
    # Replace the card of all Better Thermostat entities …
    - match: { integration: better_thermostat, domain: climate }
      card:
        type: custom:better-thermostat-normal-climate-card
    # … and adjust it for one of them (no `type` = merged into the current card)
    - match: { entity: climate.bathroom }
      card: { name: Bathroom }
    # Cameras as picture cards, only in the highlighted area sections
    - match: { domain: camera }
      contexts: [area]
      card: { type: picture-entity, show_state: false }
    # Hide entities with a label
    - match: { label: dashboard-hidden }
      card: false
    # One card per device instead of one tile per entity
    - match: { label: virt-guest }
      scope: device
      card:
        type: entities
        title: $device
        entities: $entities
```

- Rules are evaluated in order and **all** matching rules apply. A `card` with a different `type`
  replaces the card, a `card` without `type` is merged into it, `card: false` hides the entity.
  `stop: true` ends the evaluation for that entity.
- `entity` is set automatically unless the card uses the `$entity` placeholder.
  Placeholders: `$entity`, `$device`, `$area`, and `$entities` (device scope, list of entity ids).
- `contexts` limits where a rule applies: `favorites` (favorites and suggested entities on the
  overview page), `area` (highlighted sections of an area view), `area_other` (remaining devices of
  an area view), `media` (media players view), `devices` (devices view). In the devices view every
  device is one entities card: device rules replace it, entity rules can only hide rows.
- `scope: device` turns all entities of a matching device into one card (first matching rule wins).

### Area overrides

```yaml
strategy:
  type: custom:overview-plus
  area_overrides:
    proxmox:                         # area id
      badges: false                  # or a list of entity ids; default: area temperature/humidity
      sections:
        - title: Hypervisor
          icon: mdi:server
          match: { label: virt-hypervisor }
          layout: devices
        - title: VMs & containers
          icon: mdi:cube-outline
          match: { label: virt-guest }
          layout: compact
          primary: { domain: binary_sensor, device_class: running }
        - title: Exporter
          icon: mdi:access-point-network
          match: { integration: mqtt, manufacturer: Proxmox }
          entities:
            include_domains: [sensor, binary_sensor]
      show_other_devices: true       # default
      show_automations: true         # default
      tile:                          # the area's tile on the overview page (area card options)
        sensor_classes: []           # default: [temperature] if the area has a temperature sensor
        alert_classes: [problem]
        color: blue
```

`tile` options are merged into the area card on the overview page; any option of the area card
can be used. An area can have a `tile` without `sections` – its area view then stays the default.

The area card can only show values combined by device class (e.g. the median temperature of the
area). To show specific entities instead – also diagnostic sensors and sensors without device
class – list them under `tile.entities`; the tile then uses Overview Plus' own area tile, which
looks like the compact area card:

```yaml
      tile:
        entities: [sensor.pve_cpu, sensor.pve_memory]   # shown in this order
        show_names: true                                 # "CPU 12 % · RAM 41 %"
        alert_entities: [binary_sensor.vm_db_running]    # badge while one of them is on
        alert_classes: [problem]
```

When an area has `sections`, the standard categories (lights, climate, security, media players,
scenes) are not built. The configured sections are shown in order, followed by all remaining devices
of the area and its automations, as in the default view.

- A **device** belongs to the first section that matches any of its entities; later sections and the
  remaining-devices list do not show it again.
- `layout`:
  - `tiles` (default): one tile per entity.
  - `devices`: a heading per device with its entities.
  - `compact`: one tile per device showing its primary entity, named after the device, opening the
    device page. The primary entity is chosen by `primary` (match spec) or automatically
    (running/connectivity/power sensor, switch, binary sensor, sensor).
  - `table`: one entities card per device.
- `entities` narrows which matched entities are shown: `include_domains`, `exclude_domains`,
  `include_categories` (default `[none, diagnostic]`, i.e. configuration entities are hidden),
  `exclude_device_classes`, `exclude` (entity ids).
